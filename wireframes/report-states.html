Wireframe — HTML report states

Disposable sketch for Dev Team 3. Three views of the same shell: No (coverage sells the scan), Few (findings + remaining clear classes), Many (grouped, severity-first). Not product UI — layout only. Data shape assumes ScanResult + detector classes.

Hard problem called out by Steve: Findings = 0 must still show value. Empty state leads with attestation (“N of N classes clear”), OWASP categories covered, scan proof, and explicit limits — not a blank “all clear” banner alone.

Scan limits & next steps

Why “clean” is not “done”:
  • Auth walls and non-public hosts were not in scope.
  • CT / DNS discovery gaps — hosts we never saw stay unchecked.
  • No live key validation; patterns are heuristic / confirmed by presence only.
  • Suggested next: expand Extra hosts, re-run after deploy windows, add Plan 1–3 detectors when shipped.

Sketch note: empty state never ends on “No AI exposure findings.” Lead with coverage, then limits.
